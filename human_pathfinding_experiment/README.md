# Human Pathfinding Experiment Web Application

Participants manually navigate an aircraft around time-varying thunderstorm obstacles; every
attempt is stored in Postgres as raw route data for post-hoc analysis. The experiment design,
checklist and status are described in `EXPERIMENT_PLAN.md` / `EXECUTION_REPORT.md`.

## Quick Start (local, self-contained)

Requires `data/` and `config/` from the repository root and a `.env` with `POSTGRES_PASSWORD`
(see `.env.example`).

```bash
docker compose up -d --build
```

The backend container applies alembic migrations, seeds the condition-order schemes and the
11 experiment timestamps (shuffled into 11 triples) on startup, then serves the API.

- Frontend: http://localhost:3000
- Backend API: http://localhost:8000
- API Documentation: http://localhost:8000/docs

## Deployment (production)

| Component | Host | Notes |
|---|---|---|
| Frontend | **Vercel** (free) | Static Vite build; `/api/*` is proxied to the backend via `frontend/vercel.json` rewrites |
| Backend | **Render** (free, Docker) | Blueprint in `render.yaml`; free instances spin down after ~15 min idle — warm up with a request to `/health` a few minutes before the session |
| Database | **Supabase** or **Neon** (free Postgres) | Connection string goes into the backend `DATABASE_URL` env var |

### Step-by-step

1. **Database**: create a free Postgres project (Supabase/Neon), copy the connection string.
2. **Backend on Render**: Dashboard → New → Blueprint → select this repository
   (root directory `human_pathfinding_experiment`), then set the env vars:
   - `DATABASE_URL` — the managed Postgres connection string
     (`postgres://…` and `postgresql://…` are normalized to the psycopg2 driver automatically)
   - `DATA_ARCHIVE_URL` — HTTPS URL of the dataset archive (next step)
   - `CORS_ORIGINS` — the Vercel frontend URL (comma-separated allowlist)
   - `JWT_SECRET`, `ADMIN_TOKEN` — generated by the blueprint
3. **Dataset archive**: build and upload once (≈ 97 MB compressed, 11 timestamp directories
   + `config/*.pkl`, split into parts below the 50 MB per-file limit of Supabase Storage free
   tier):
   ```bash
   python3 scripts/build_data_archive.py          # writes deploy/data.tar.gz.part-00 / -01 / -02
   # upload all parts to Supabase Storage (public bucket) and set DATA_ARCHIVE_URL to the
   # comma-separated list of their URLs in part order
   ```
   The backend container downloads the parts at start, concatenates and unpacks them when the
   dataset is missing (`backend/scripts/fetch_data.py`), then applies migrations and seeds
   reference data.
4. **Frontend on Vercel**: import `human_pathfinding_experiment/frontend` as a project, then put
   the Render backend URL into `frontend/vercel.json` (replace
   `REPLACE-WITH-BACKEND-URL.onrender.com`).

### Admin endpoints

Protected by the `X-Admin-Token` header (value of the `ADMIN_TOKEN` env var); disabled entirely
(404) when `ADMIN_TOKEN` is unset — this keeps local docker-compose development simple.

- `GET /api/admin/summary` — live session progress for the experiment day: participants,
  trials by status, submitted counts per condition, latin-square scheme balance
- `GET /api/admin/export` — all trials with participant identity as CSV for the analysis script
- `GET /api/results`, `GET /api/results/{filename}`, `POST /api/results` — legacy parquet
  storage, admin-only since the experiment frontend does not use it

## User Flow

1. **Login**: surname / name / group (a secret ДЕМО button starts an anonymous demo session,
   nothing is persisted). The participant is created on the fly; identity is unique, completed
   participants cannot log in again.
2. The backend assigns a latin-square scheme and 3 trials (condition C0/C1/C2 × timestamp);
   the participant never picks anything manually — the screen just shows «Сценарий N из 3».
3. **Navigate**: click on the canvas to place waypoints; arrow keys switch forecast layers
   and zoom, Enter confirms a 75 km segment (5 min of flight at 900 km/h).
4. **Submit**: raw segments are stored (no client-side metrics are trusted); after the third
   trial the participant answers the final 5-question questionnaire.

## API Endpoints

| Method | Endpoint | Description |
|--------|----------|-------------|
| POST | `/api/participants/login` | Login / create participant on the fly, issue session JWT |
| POST | `/api/participants/demo` | Anonymous demo token (nothing is stored) |
| POST | `/api/participants/me/questionnaire` | Final questionnaire, marks the session complete |
| GET | `/api/trials/next` | Next assigned trial (condition + timestamp parameters) |
| POST | `/api/trials/{id}/start` | Fix server-side start time, status → `in_progress` |
| POST | `/api/trials/{id}/submit` | Store raw `all_paths` / `path` + interaction counters |
| POST | `/api/obstacles` | Obstacle layers for the current position (JWT required) |
| POST | `/api/obstacles/bbox` | Pixel transform + time keys for the timestamp |
| POST | `/api/obstacles/validate` | Live path validation feedback |
| GET | `/api/ab-points?timestamp=...` | A and B points for the timestamp |
| GET | `/api/admin/summary` | Admin: session progress (X-Admin-Token) |
| GET | `/api/admin/export` | Admin: trials CSV export (X-Admin-Token) |

## Configuration

Backend env vars (see `backend/app/config.py`):

| Variable | Purpose |
|---|---|
| `DATABASE_URL` | Postgres connection string |
| `JWT_SECRET` | Signing key for participant session tokens |
| `ADMIN_TOKEN` | Shared secret for `/api/results*` and `/api/admin/*` (unset = endpoints disabled) |
| `CORS_ORIGINS` | Comma-separated origin allowlist (default: local dev ports) |
| `DATA_ARCHIVE_URL` | Dataset tar.gz fetched at container start when the dataset is missing |
| `DATA_PATH`, `CONFIG_PATH`, `RESULTS_PATH` | Volume mount points (defaults fit the container) |

## Architecture

```
human_pathfinding_experiment/
├── backend/
│   ├── app/
│   │   ├── main.py          # FastAPI entry point (CORS allowlist, routers)
│   │   ├── config.py        # Pydantic settings (env-driven)
│   │   ├── routers/         # API endpoints (auth, admin, obstacles, trials, ...)
│   │   ├── services/        # Business logic (geometry, validation, participants)
│   │   ├── db/              # SQLModel models, engine
│   │   └── schemas/         # Pydantic models + StrEnums
│   ├── alembic/             # Migrations
│   ├── scripts/             # seed_experiment_data.py, fetch_data.py
│   └── Dockerfile
├── frontend/
│   ├── src/
│   │   ├── components/      # React components
│   │   ├── hooks/           # useExperiment state machine
│   │   ├── services/        # API client (in-memory JWT)
│   │   ├── types/           # TypeScript types
│   │   └── utils/           # Geometry, colors, conditions
│   ├── vercel.json          # /api rewrite to the backend + SPA fallback
│   └── Dockerfile
├── scripts/
│   └── build_data_archive.py  # builds deploy/data.tar.gz for DATA_ARCHIVE_URL
├── render.yaml              # Render blueprint (backend)
└── docker-compose.yml       # local stack: db + backend + frontend
```
